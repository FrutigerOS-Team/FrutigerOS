Troubleshooting

Symptoms we have actually hit while developing the tree, and how to diagnose them.

Build failures

pkg-config cannot find wayland-client

Install the Wayland development packages and pkgconf:

sudo pacman -S wayland wayland-protocols pkgconf libxkbcommon

Smithay fails to compile against a newer Rust

Smithay 0.3 is pinned. The warning about future-incompatible code comes from the dependency, not from FrutigerOS. Build with the current stable toolchain and do not patch the lockfile unless you intend to migrate the compositor.

rustup update stable
rustc --version   # 1.75 or newer

cargo fmt --check fails on a crate you did not touch

Formatting is per-crate. Run it from the crate root, and for the applications workspace use --all:

(cd aerowm && cargo fmt)
(cd aeroshell && cargo fmt)
(cd aero-installer && cargo fmt)
(cd aero-apps && cargo fmt --all)

Runtime problems

AeroWM exits immediately: cannot create a window

The winit backend needs a host display. Check that WAYLAND_DISPLAY or DISPLAY is set and points at a live compositor. Running from a bare TTY will fail by design.

echo "$WAYLAND_DISPLAY"
echo "$DISPLAY"
loginctl show-session "$XDG_SESSION_ID" -p Type

AeroShell connects but no panel appears

  • Check that WAYLAND_DISPLAY matches the socket printed by AeroWM (often wayland-1, not wayland-0).
  • Look for the Promoting surface … to AeroPanel log line in AeroWM.
  • The panel is only promoted after its first commit; wait a frame.
  • Confirm app_id is exactly frutigeros-aeropanel.

The panel shows the wrong active workspace

Expected. There is no AeroWM → AeroShell IPC yet, so the panel always renders workspace 0 as active. This is a known limitation, not a configuration error.

Panel text is missing glyphs

The built-in 5×7 font only covers digits, A–Z, space and a few punctuation marks. Lower-case input is rendered as-is; unsupported glyphs are blank. This avoids a fontconfig dependency on the live medium.

Installer

“no partition plan” error

The Installing step ran before Partitioning. In the CLI wizard this cannot happen; if you drive InstallerState programmatically, set choices.partition_plan first.

--apply refuses to run

Destructive execution requires both --apply and --yes. This is intentional. Run without flags to inspect the plan.

cargo run                 # dry-run
cargo run -- --apply --yes  # destructive

lsblk: not found

Install util-linux. The installer probes disks with lsblk --json and does not fall back to parsing /proc/partitions.

ISO

build.sh says mkarchiso was not found

Install archiso on Arch Linux: sudo pacman -S archiso. Profile validation (./build.sh --check) works without it.

The live session drops to a shell

Expected on bare metal today. frutigeros-session looks for an existing DISPLAY/WAYLAND_DISPLAY; AeroWM has no DRM backend yet. Start Xorg or run inside a nested compositor.

QEMU boots to an archiso “medium not found” prompt

The archisolabel in the boot entry must match the generated ISO label. The profile uses %ARCHISO_LABEL%; if you edited it to a literal, rebuild the ISO.
