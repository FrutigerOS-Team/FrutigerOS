Installation

Two independent paths: build the live ISO, or run the installer backend against a prepared target.

No boot-tested ISO exists yet. The archiso profile passes static validation (./build.sh --check), but it has not been built or booted in QEMU in the current development environment. Treat every ISO produced from this tree as experimental.

1. Validate the ISO profile

The validation script needs no root and no archiso installation.

cd frutigeros-iso
./build.sh --check

It checks required files, shell syntax, executable bits, and that boot entries use the %ARCHISO_LABEL% placeholder.

2. Build the ISO

mkarchiso mounts filesystems and must run as root. Install archiso first.

sudo pacman -S archiso
cd frutigeros-iso
sudo ./build.sh --out ./out --work /tmp/frutigeros-work

The image is written to out/frutigeros-<date>-x86_64.iso.

Desktop packages are the remaining blocker

The profile boots Arch Linux with FrutigerOS branding and configuration. To get a graphical live session, build packages for aerowm, aeroshell, aero-installer and the asset packages, serve them from a local repository, then enable the [frutigeros] section in frutigeros-iso/pacman.conf and the matching entries in packages.x86_64.

3. Test in QEMU

Install qemu-full and boot with UEFI firmware. The ISO label is generated at build time; archisolabel is substituted by archiso.

qemu-system-x86_64 \
  -enable-kvm -m 4096 -smp 4 \
  -drive if=pflash,format=raw,readonly=on,file=/usr/share/OVMF/OVMF_CODE.fd \
  -drive if=pflash,format=raw,file=/tmp/OVMF_VARS.fd \
  -cdrom frutigeros-iso/out/frutigeros-*-x86_64.iso \
  -boot d

At the boot menu choose FrutigerOS Live. The live session currently falls back to a shell on a bare TTY because AeroWM's winit backend requires an existing display server.

4. Run AeroInstaller

The installer CLI is a complete wizard state machine with a command planner. Dry-run is the default.

cd aero-installer

# Safe: probes disks, prints the plan, executes nothing
cargo run

# Destructive: requires both flags
sudo cargo run -- --apply --yes

What the plan contains

  1. sgdisk --zap-all and partition creation (EFI, boot, swap, root).
  2. mkfs.fat / mkfs.ext4 / mkfs.btrfs / mkswap.
  3. Mount root, boot and EFI, then enable swap.
  4. pacstrap and genfstab.
  5. Locale, timezone, hostname, user and sudo configuration through arch-chroot.
  6. GRUB installation and grub-mkconfig (UEFI or BIOS).
  7. umount -R.
Safety contract. The planner refuses unconfirmed partition plans. --apply is rejected unless --yes is also present. Only clean installs are supported; alongside and manual modes return an error instead of guessing a layout. Disk probing uses lsblk and is read-only.

Manual install (current workaround)

Until the ISO ships desktop packages, install Arch normally and build the components from source:

# on the target Arch system
sudo pacman -S rustup wayland libxkbcommon mesa
git clone https://github.com/frutigeros/frutigeros.git
cd frutigeros

(cd aerowm && cargo build --release)
(cd aeroshell && cargo build --release)

sudo install -Dm755 aerowm/target/release/aerowm /usr/local/bin/aerowm
sudo install -Dm755 aeroshell/target/release/aeroshell /usr/local/bin/aeroshell
