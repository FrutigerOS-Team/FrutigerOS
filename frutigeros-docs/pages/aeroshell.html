AeroShell

The desktop shell: a real Wayland panel rendered in software, an XDG launcher, and a notification pipeline.

The panel is a real surface

AeroShell connects to AeroWM as an ordinary Wayland client. It binds wl_compositor, wl_shm and xdg_wm_base, creates an xdg toplevel, and commits an ARGB8888 shared-memory buffer. AeroWM identifies the panel by app_id. 

pub const APP_ID: &str = "frutigeros-aeropanel";

// AeroWM pins this app_id to the bottom edge, full width,
// above normal windows and outside workspace management.
Why not wlr-layer-shell? Smithay 0.3 does not provide a server-side layer-shell module. Rather than adding an unmaintained protocol implementation, the panel is a toplevel with a reserved app_id, special-cased by the compositor.

Rendering pipeline

  1. Compute a layout for the configured width and height.
  2. Draw into a tiny-skia pixmap: deep-ocean gradient, gloss and border, start orb, workspace dots, tagline, clock/date, tray glyphs, quick-settings pill.
  3. Convert RGBA pixmap pixels to premultiplied ARGB8888.
  4. Copy into a tempfile-backed wl_shm pool.
  5. Attach, damage, commit; wait for buffer release before reuse.

The clock requests a redraw on the next minute boundary using a libc::poll timeout, so the event loop stays idle between ticks.

Dependency-free text

Text is drawn with a built-in 5×7 bitmap font (glyphs.rs) rather than fontconfig/FreeType. This keeps the live ISO deterministic and avoids a runtime font dependency. It covers digits, A–Z, :, ., -, / and space.

Layout model

Items are placed left-to-right, with the right-hand group measured from the right edge:

[Start] [WS1 WS2 WS3 WS4] [── tasks ──] [Clock] [Tray] [Quick settings]

The layout engine is pure and unit-tested: the items always cover the configured width, four workspaces are present by default, and start/clock items exist.

AeroStart launcher

launcher.rs discovers .desktop files from XDG data directories, parses name/exec/icon fields, strips field codes (%f, %U, …), and provides case-insensitive search. Launching spawns the cleaned command.

let apps = launcher::discover_apps();
let hits = launcher::search(&apps, "term");
launcher::launch(&hits[0])?;

The popup surface is not implemented yet; the data layer is complete and tested.

Notifications

notifications.rs models a notification queue with summary, body, urgency, expiry and a visible-count cap. The async daemon task is wired into main.rs, but D-Bus delivery and toast surfaces are pending.

Configuration

Read from ~/.config/aeroshell/config.toml:

[panel]
height = 48
position = "bottom"
show_workspaces = true
show_clock = true
show_tray = true
launcher_key = "Super+Space"

[launcher]
recent_count = 6
favorites_count = 8

[notifications]
duration_ms = 5000
corner = "top-right"
max_visible = 5
Known limitation. The panel currently hard-codes active_workspace = 0: there is no AeroWM → shell IPC yet. Workspace changes in the compositor are not reflected in the panel, and the clock is the only live element.
